The database query has a fake 300 ms delay to act like a heavy query. A MISS pays that cost; a HIT skips the database and comes back in a few ms.

🧪 Try these experiments

  1. Cache: Refresh twice. First is MISS (~300 ms), second is HIT (a few ms).
  2. TTL: Wait 60 seconds without touching anything, then refresh. It's a MISS again because the key expired.
  3. Invalidation: Upload a photo. The cache is deleted right away, so you see your photo immediately instead of a stale feed.
  4. Rate limiting: Upload 6 photos within a minute. The 6th is blocked.
  5. Sharding: Look at the shard badges. Each photo is saved in only one table, and the feed asks both tables and merges them (scatter-gather).
  6. Browser cache: Open DevTools → Network and refresh. The images come "from disk cache" and never hit the server.
